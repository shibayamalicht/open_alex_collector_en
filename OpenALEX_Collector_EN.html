🔑 OpenAlex API Key
Since February 13, 2026, an API key is required to use the OpenAlex API. The old mailto (polite pool) method has been retired. Without a key, requests run on a small trial allowance of about 100 requests per day and then fail with errors such as 403. Creating a free account gives you up to 100,000 credits per day (about $1/day worth: unlimited single-work lookups, 10,000 list/filter calls, 1,000 full-text searches, 100 full-text downloads, etc.) at no cost.
Note: the breakdown above is a per-operation-type guideline. This tool fetches paper metadata only and never performs "full-text downloads" (downloading a paper's PDF body), so the "100 full-text downloads/day" limit never applies — normal research stays well within the free search/listing allowance.

How to get an API key (about 30 seconds, free)

  1. Go to openalex.org and create a free account (email only).
  2. Once signed in, open openalex.org/settings/api (Settings → API).
  3. Copy your API key.
  4. Paste it into the field below and click Save.
If you need higher limits for academic research, contact support@openalex.org — OpenAlex can often help for free (per their official guidance).
The key is sent only to the OpenAlex API, as the api_key request parameter.
Privacy & safety: Your key is stored only in this browser's localStorage and is never sent anywhere except the OpenAlex API (this tool is a single HTML file with no backend of its own). On a shared computer, click Clear when you are done. Never share your key with others.

ID Author / Institution Disambiguation
Disambiguation: Authors are aggregated primarily by OpenAlex Author ID / ORCID, and institutions by OpenAlex Institution ID / ROR. In v7, computation caches are kept in memory only, and disambiguation maps are not auto-saved. Save them explicitly per dataset only when you want to reuse them.
Institution aggregation unit
The safest default is “Exact ID.” Parent institution grouping uses OpenAlex lineage, but only aggregates to parent IDs whose names are known. If the parent name is unknown, the original institution name is preserved, so ID-only nodes such as “Parent institution I...” are not created.

Disambiguation Workbench

How to use: Switch the target between “Author” and “Institution,” then open “Details / merge” for a row. In the popup, review papers, co-authors/collaborators, Topics, and same-name candidates while merging entities. “Split” removes merge rules created by clicking and returns the entity to its original OpenAlex ID/ROR or “name-only (no ID)” unit.
For bulk merge, the first checked key in the current display order becomes the target. To explicitly choose the target, open “Details / merge” in the row. The current map is not auto-saved. Use “Save for this dataset” or JSON export when you want to reuse it.

Citation-based analysis: Rank authors, institutions, and journals by citations (quality / impact) rather than count (volume). h-index is a standard volume × impact indicator. Recalculated with the “Render” button in each tab.

RL Must-read Papers & Technology Lineage
Reading order and lineage: Must-read Papers and Technology Lineage are merged into one card. Papers included in the lineage can be automatically added to the reading candidates even if they are outside the score Top-N.
Paper triage: Ranks candidate papers by an explainable score using Topic burst, age-adjusted citations, bridging signal, technical keyword novelty, author/institution signal, and funding signal.
The Top-N value controls score-ranked papers. When “Include lineage nodes” is ON, lineage papers outside the Top-N are also shown. Imported AI results add category, reading order, and reason.
Recalculate to display must-read paper candidates.
Paper lineage: Builds a left-to-right tree/DAG by prioritizing internal citation. If direct citation is unavailable, it estimates parent-child relations by Topic continuity, TF-IDF keyword similarity, co-author/institution continuity, and bibliographic coupling. Click a node for paper details or an edge for relationship reasons. Imported AI technical points update labels and explanations for all nodes.
Lineage logic: Parent-child relation = direct citation first. If direct citation is absent, the tool selects the closest prior parent candidate using Topic match, technical-keyword Jaccard similarity, author/institution overlap, and shared references. Edges are prior paper → later paper. Increase the minimum relation score to remove weak inferred edges.
Automatically displayed after search or CSV import. Press Render if it does not appear.
